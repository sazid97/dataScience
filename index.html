Tools reference
Every tool in the job description — what it is, what it does, and how your existing skills connect.
AZ
Azure Databricks
Cloud data platform · Apache Spark
A unified analytics platform built on Apache Spark. You write notebooks in Python/SQL, and Databricks runs your code across a cluster of machines — processing billions of rows in minutes instead of hours.
Your bridge: Databricks notebooks look and feel like Jupyter. PySpark DataFrame API is 80% the same as Pandas — just distributed.
SF
Snowflake
Cloud data warehouse · SQL
A cloud-native data warehouse where you query massive datasets using standard SQL. It separates storage from compute — meaning you can scale query power independently of storage cost.
Your bridge: You already know SQL. Snowflake SQL is standard ANSI SQL — just learn COPY INTO, stages, and virtual warehouses as new concepts.
IC
Apache Iceberg
Open table format · Storage layer
An open table format for huge datasets sitting in cloud storage. It gives your raw files superpowers: time travel (query old versions), schema evolution (add columns without breaking things), and hidden partitioning.
Your bridge: Think of it like a smarter, versioned CSV with a built-in index. Your Pandas knowledge of DataFrames makes the concept intuitive.
MF
Microsoft Fabric
Unified analytics platform · SaaS
Microsoft's all-in-one analytics platform that combines data engineering, warehousing, real-time analytics, and Power BI into a single product. Built on OneLake — one storage lake for everything.
Your bridge: Fabric Notebooks use PySpark — same as Databricks. If you know one, you can navigate the other quickly.
EH
Azure Event Hubs
Streaming ingestion · Kafka-compatible
A big data streaming platform that ingests millions of events per second. Think of it as a massive, highly durable message queue — producers send events, consumers process them in real-time.
Your bridge: You can produce events with the Python azure-eventhub library — familiar territory. Consuming is new but follows a simple read loop pattern.
AD
Azure DevOps
CI/CD + project management · DevOps
Microsoft's DevOps platform combining Git repositories, CI/CD pipelines, Agile boards, and artifact storage. For data engineers it means automated testing and deployment of your notebooks and pipelines.
Your bridge: If you know Git, you know 60% of Azure DevOps Repos. YAML pipelines are new syntax but logical once you understand the trigger → job → step structure.
PS
PySpark
Distributed computing · Python API
The Python API for Apache Spark — lets you write distributed data processing code using a DataFrame API. Transforms, joins, aggregations work across a cluster of machines instead of one computer.
Your bridge: df.select() ≈ pandas df[[cols]], df.filter() ≈ df[condition], df.groupBy().agg() ≈ df.groupby().agg(). Almost a 1:1 translation.
DL
Delta Lake
Open storage format · ACID transactions
An open-source storage layer that brings ACID transactions and versioning to data lakes. It's the default format in Databricks — your Parquet files get a transaction log that enables time travel, merge, and upsert operations.
Your bridge: You write Delta tables the same way you'd write Parquet in Pandas/PySpark. The format handles the reliability layer automatically underneath.
Glossary — key terms to know
Definitions for the terms you'll hear daily. Each has a plain-English analogy tied to things you already know.
Data Lakehouse
An architecture that combines the cheap storage of a Data Lake with the reliability and query performance of a Data Warehouse. You store raw files in cloud storage but layer ACID transactions on top so it behaves like a database.
Analogy: A messy warehouse (lake) that has been given a proper inventory system and aisle labels (warehouse features).
ETL / ELT
ETL = Extract, Transform, Load. You pull data from a source, clean/shape it, then load it to a destination. ELT = Extract, Load, Transform — load raw first, transform inside the warehouse. Modern cloud stacks mostly use ELT because compute is cheap.
Analogy: ETL is like cooking before serving. ELT is like serving raw ingredients and cooking at the table.
Medallion architecture
A data design pattern with three layers — Bronze (raw, untouched), Silver (cleaned and validated), Gold (aggregated, business-ready). Each layer adds trust and structure to the data.
Analogy: Like refining ore — raw rock (Bronze) → purified metal (Silver) → finished product (Gold).
Data ingestion pipeline
Automated code that moves data from a source system (database, API, file) into your data platform on a schedule or in real-time. The main job responsibility — you'll build many of these.
Analogy: Like an assembly line that automatically collects packages from many suppliers and puts them in your warehouse.
ACID transactions
Atomic, Consistent, Isolated, Durable. A guarantee that database operations either fully succeed or fully fail — no partial writes. Critical for data reliability when multiple processes write simultaneously.
Analogy: Like a bank transfer — either both accounts update or neither does. Never half-done.
Time travel (data)
The ability to query a table as it existed at a specific point in the past. Powered by Delta Lake and Iceberg transaction logs. Lets you audit changes, recover from bad writes, or reproduce historical reports.
Analogy: Like Git history for your data — you can checkout any past commit.
Schema evolution
The ability to add, rename, or change columns in a table without breaking existing pipelines or readers. Iceberg and Delta Lake handle this automatically — traditional Parquet does not.
Analogy: Like adding a new column to a Pandas DataFrame without crashing every script that was already reading it.
Structured Streaming
Apache Spark's engine for processing continuous streams of data using the same DataFrame API as batch processing. You define a query once — Spark runs it continuously as new data arrives.
Analogy: Like a Pandas script that doesn't stop — it processes each new row the moment it arrives, forever.
Virtual warehouse (Snowflake)
Snowflake's term for a compute cluster. You can spin up multiple warehouses of different sizes and pause them when not in use — you only pay while running. This separation of storage and compute is Snowflake's core innovation.
Analogy: Like renting different-sized CPU from a cloud — small for reports, XL for heavy transformations, then shut it off.
RBAC (Role-Based Access Control)
A security model where permissions are assigned to roles (not individual people), and users are assigned roles. In Azure, roles control who can read/write/delete specific resources. Required for enterprise data security compliance.
Analogy: Like a job title system — "admin" can do everything, "analyst" can only read. You assign titles, not individual permissions.
Managed identity
An Azure feature that gives a cloud service (like Databricks) its own identity to authenticate to other services (like ADLS) — without storing any passwords or keys in your code. The safest way to connect Azure services.
Analogy: Like a staff badge that automatically opens the doors you're allowed in — no keys to lose or share.
Agile / Sprint
Agile is a work methodology using short delivery cycles called sprints (usually 2 weeks). Each sprint has a planning meeting, daily standups, and a retrospective. Work is broken into user stories with clear acceptance criteria.
Analogy: Instead of building the whole product then shipping, you build and ship a small working slice every 2 weeks.
CI/CD pipeline
Continuous Integration / Continuous Delivery. Automated process: when you push code → tests run automatically → if they pass → code deploys automatically. In Azure DevOps this is a YAML file defining these steps.
Analogy: Like a quality checkpoint belt — every new item on the belt gets automatically tested before reaching the customer.
Data Lake (ADLS Gen2)
Azure Data Lake Storage Gen2 — a hierarchical file system in Azure for storing any type of data (structured, semi-structured, unstructured) at massive scale at very low cost. The foundation of your data architecture.
Analogy: Like a massive hard drive in the cloud — you dump everything in and organize it with folders. Much cheaper than a database per GB.
Proof of concept (POC)
A small, fast prototype built to test whether a technical approach works before committing to building the full production system. The job mentions conducting POCs with bottlers — you build a mini version, measure value, then productionize.
Analogy: Like a cooking trial run before cooking for 100 guests — you validate the recipe works first.
Lazy evaluation (Spark)
Spark doesn't execute your DataFrame transformations immediately — it builds a plan of what to do. Execution only happens when you call an action like .show(), .count(), or .write(). This is the biggest mental shift from Pandas.
Analogy: Like writing a recipe vs actually cooking. Spark writes the recipe as you type, but only cooks when you say "serve it."
